## Retry classes (derived from each code's registered `outcome`, `persist_failure`, `retryable`)

| Class | Rule | UI (docs/17 L2 command layer) |
|---|---|---|
| `RETRY_SAME_INTENT` | `UNKNOWN_OUTCOME`, or `ROLLED_BACK` + retryable (no effect committed) | "Result unknown / temporary error": offer **Retry (same command)**; same `X-Command-Id`, same body and CAS |
| `ALREADY_DONE_READ_STATE` | `COMMITTED_REPLAYABLE` | the command already happened: refresh the server state, show it as done |
| `REFRESH_THEN_DECIDE` | `CONCURRENCY_CONFLICT` (stale version) | refetch; show the new state; the operator confirms again as a **new** intent (new id, new CAS) |
| `APPROVAL_FLOW_SAME_ID` | `APPROVAL_REQUIRED` (not persisted) | open the manager approval (`Approval.Grant`), then resubmit the **same** command id with `approvalGrantId` |
| `REAUTHENTICATE_SAME_ACTOR` | `UNAUTHENTICATED` | log in again **as the same user**; never replay under another actor |
| `RETRY_SAME_INTENT_AFTER_DELAY` | `RATE_LIMITED` | wait, then same command |
| `NOT_PERMITTED` | `PERMISSION_DENIED`, `APPROVER_NOT_AUTHORIZED`, `SELF_APPROVAL_DENIED` | show "not allowed"; no retry; a different authorized person acts under **their own** login or approval |
| `CLIENT_DEFECT_NEW_INTENT` | `IDEMPOTENCY_KEY_REUSED_WITH_DIFFERENT_REQUEST` | a UI defect (an id reused with another body): log it, never auto-retry; the operator starts a new intent |
| `FIX_AND_RESUBMIT` | `REJECTED`, not persisted | show the reason; the operator corrects the input; the same id may be reused with the corrected body |
| `FINAL_NEW_INTENT_ONLY` | `REJECTED`, persisted (`persist_failure`) | show the reason; the same id would replay this failure, so any new attempt is a new intent with a new id |

A **transport failure or timeout after sending** is `RETRY_SAME_INTENT` (adapter state `UNKNOWN`); a failure **before sending** is safe to resend (`NOT_SENT`).
