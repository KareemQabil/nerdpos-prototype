# NerdPOS — بروتوتايب للتجربة (Expert Prototype)

نسخة تجريبية كاملة لسيستم كاشير مطاعم مصري **من غير باك إند**: كل الطلبات بتتمسك جوه المتصفح وبتعدي على
"سيرفر وهمي" مبني من العقود الحقيقية (`operations.json` و `errors.json` و `openapi`) وقواعد `02_MOCK_RULES`.
نفس أكواد الأخطاء، ونفس الصلاحيات، ونفس قواعد الموافقات وعدم تكرار الطلب.

> **مش منتج حقيقي.** مطعم تجريبي ("مطعم الحاج سامي للمشويات") وبيانات وهمية متخزنة في المتصفح. مفيش دفع حقيقي
> ولا اتصال بمنظومة ضرايب حقيقية.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # نسخة static في dist/ (base './' — تتفتح من أي مكان، أو Vercel)
npm run artifact   # نفس النسخة + dist/artifact.html للنشر كـ Artifact على claude.ai
```

المتطلبات: Node 18+. `npm run dev` بيولّد `src/contracts/*.json` من `docs/pack/` الأول.

## أول ما تفتح

شاشة ترحيب بتشرح الديمو في سطرين، وفيها **"جرّب كـ…"**: ويتر، كاشير، المطبخ، مدير، صاحب المطعم، أو تركيب مطعم من
الصفر. كل اختيار بيدخّل الجهاز الصح ويفتح الشاشة الصح (وممكن الرحلة المناسبة). ترجعلها من زرار **مساعدة**.

## الأجهزة

كل جهاز في الشريط اللي فوق ليه دخوله وجلسته وشاشته كأنه جهاز منفصل. زرار **جهازين** بيعرض جهازين جنب بعض (مثلاً
الويتر والمطبخ) وأي تغيير بيظهر على الاتنين فوراً.

| الجهاز | بيستخدمه | ملاحظات |
|---|---|---|
| الويتر (تابلت) | الويتر | الصالة والشيكات، من غير درج |
| الكاشير (عليه درج) | الكاشير | الوردية والدفع والتيك أواي والدليفري والإيصال الإلكتروني |
| المطبخ | الشيف | شاشة المطبخ والجرد والهالك والتحضير |
| المدير | المدير / المالك | الإدارة والتقارير والموافقات |
| الفرع التاني | ويتر الفرع التاني | منيو الفرع التاني |
| التيك أواي | كاشير تاني | درج تاني (لنقل الشيكات بين الأدراج) |
| الإدارة (من غير جهاز) | الباك أوفيس | الإعدادات من أي مكان |

## اللي في السيستم

القائمة الجانبية مقسمة أقسام، وفيه بحث سريع عن أي شاشة (**Ctrl+K**).

- **الخدمة:** الصالة بخريطة حقيقية (أقسام، حالة كل ترابيزة، وقت القعدة، الترابيزة محتاجة تنضيف)، الشيك (دفعات للمطبخ،
  مقاعد، خصومات، تقسيم ودمج ونقل)، نقطة البيع، الشيكات، شاشة المطبخ (مؤقتات، مستعجل، إعادة تحضير، نقل لمحطة،
  المطلوب كله، شاشة التسليم)، الحجوزات والعربون، "خلص النهارده".
- **الفلوس والوردية:** الدفع (كاش بأزرار سريعة، كارت، محفظة، نقاط، أكتر من طريقة)، المرتجعات بموافقة مدير تاني، الوردية
  والدرج (عدّ بالفئات، X/Z)، نقل الشيكات لدرج تاني، **قفل اليوم**، **المطابقة** (الدرج والكارت والمحافظ والإيصالات).
- **الدليفري:** طلب دليفري برقم التليفون والعنوان والمنطقة، لوحة توزيع وخريطة، الطيارين وتسوية الكاش، مناطق التوصيل،
  **الطلبات الأونلاين** من التطبيقات والموقع وواتساب.
- **العملاء والولاء:** ملف العميل (عناوين، طلبات، حساسية، دمج المكرر)، النقاط والفئات (فضي/دهبي/بلاتيني).
- **المخزن والمشتريات:** الخامات والأرصدة والصلاحية، المخازن، الجرد والفروقات، التحويلات، الهالك، الوصفات وتكلفة
  الطبق، التحضير، الموردين، أوامر الشراء والاستلام والمرتجع. **كل بيع بيخصم الخامات من الوصفة.**
- **المنيو والأسعار:** الأصناف بالأحجام، الوجبات (كومبو)، البيتزا نص ونص، الإضافات (بدون/خفيف/زيادة)، المنيو حسب
  الوقت (فطار/غدا/عشا) والقناة، الصور والسعرات ومسببات الحساسية، الأسعار والجدولة وتغيير الأسعار بالجملة، العروض
  (اشتري X وخد Y، أكواد، مواعيد، حدود استخدام)، استيراد المنيو من Excel.
- **التقارير:** لوحة المالك (النهارده مقارنة بإمبارح والأسبوع اللي فات، والحاجات اللي محتاجة تصرف)، 8 تقارير، رسوم،
  تصدير CSV/Excel، جدولة التقارير.
- **الإعداد:** النشاط والفروع والأجهزة، المستخدمين والأدوار، الإعدادات والأسباب، المحطات والتوجيه، خريطة الصالة
  (سحب وإفلات)، **إمكانيات النظام** (تشغيل/إيقاف الدليفري والمخزن والولاء…).
- **الضرايب والإيصالات:** الضرايب (شاملة أو فوق السعر)، التسجيل الضريبي، الإيصال الإلكتروني وإعادة الإرسال.
- **النظام:** طلبات الموافقة عن بُعد (الكاشير يبعت والمدير يوافق من جهازه)، المزامنة والأوفلاين، صحة النظام، طابور
  الطباعة، الموافقات والسجل.

## أدوات العرض (الشريط اللي فوق)

- **الوقت** — قدّم الساعة أو حطها على وقت معيّن (فطار 09:00 / عشا 20:00). اليوم التجاري بيبدأ 4 الفجر بتوقيت القاهرة.
- **محاكاة الأعطال** — وقّع الطابعة، أو شاشة المطبخ، أو منظومة الإيصال الإلكتروني، أو اقطع النت عن جهاز معيّن، أو ضيّع
  رد طلب، وشوف إن الشغل بيكمل.
- **إعدادات المطعم** — كل إعداد بكلام عادي: بيغيّر إيه، قيمته دلوقتي، وسؤال للخبير. التغيير بيطبق على العمليات الجديدة
  بس.
- **رحلات بالخطوة** — يوم صالة كامل، إلغاء شيك، إدارة الصالة والمطبخ، مرتجع، تركيب من الصفر، كاونتر، أعطال. كل خطوة:
  مين بيعمل إيه وعلى أنهي جهاز والمتوقع. "ورّيني على الجهاز" أو "خلّي السيستم يعملها".
- **سيناريوهات الفشل** — 12 سيناريو بيتشغلوا ويقولوا النتيجة، و1000 موقف مقسمين حسب الموضوع.
- **ملاحظة / ملاحظات** — دوس على أي حاجة واكتب ملاحظتك، وبعدين صدّر `feedback.json` (فيه الشاشة والجهاز والإعدادات وقتها).
- **البيانات** — رجّع بيانات العرض، أو ابدأ تركيب فاضي، أو صدّر/استورد.
- **اللغة والثيم** — عربي ↔ English، داكن/فاتح/فاخر.
- **تفاصيل تقنية** (للفريق بس، مقفول افتراضياً) — بيظهر أسماء العمليات وأكواد الأخطاء والقيم الخام وسجل الطلبات (API).

## شارة حالة الباك إند

على كل شاشة وكل قسم: **مبني** (موجود في العقد ومبني)، **متصمم** (في العقد ولسه مش مبني)، **مقترح** (مش في العقد —
البروتوتايب اقترحه؛ التفاصيل في `PROTOTYPE_GAPS.md`).

## اقتراح لترتيب التجربة

1. **رحلات بالخطوة ← يوم صالة كامل** وامشي خطوة خطوة.
2. افتح **جهازين**: الويتر + المطبخ، وابعت طلب.
3. **طلب دليفري جديد** على الكاشير ← المطبخ ← لوحة الدليفري ← الطيار يسلّم ← تسوية الكاش.
4. بيع طبق، وبعدين افتح **المخزن ← سجل الحركات** وشوف الخامات اتخصمت.
5. على الكاشير اعمل حاجة محتاجة موافقة واختار **"ابعت طلب للمدير"**، ووافق من جهاز المدير.
6. **اقطع النت** عن تابلت الويتر، ضيف أصناف، ورجّع النت وشوف المزامنة.
7. **قفل اليوم** على جهاز المدير.
8. **تركيب من الصفر** من شاشة الترحيب.

## الفلوس

العرض بالجنيه بخانتين؛ الحساب جوه بـ `decimal.js` على 4 خانات، **ومفيش float**. التسعير كله على "السيرفر الوهمي".

## هيكل المشروع

```
docs/pack/                  حزمة البروتوتايب الأصلية (المراجع)
scripts/build-contracts.mjs يولّد src/contracts/*.json من الحزمة
scripts/journeys-test.ts    تشغيل كل الرحلات و N1–N12 من غير متصفح
src/mock/                   السيرفر الوهمي: kernel (المسارات/الصلاحيات/عدم التكرار/الموافقات/الأوديت)،
                            handlers/* (طلبات، فلوس، مخزن، دليفري، عملاء، ولاء، منيو، تشغيل…)، pricing،
                            outbox (المطبخ/الطباعة/الإيصال/الربط)، clock، seed*، store
src/api/client.ts           عميل fetch + طابور الأوفلاين
src/app/                    الأجهزة، القائمة الجانبية، الهوكس، تسجيل الشاشات، زرار التفاصيل التقنية
src/screens/                شاشات التشغيل والإدارة (inventory/, delivery/, customers/, menu/, ops/, admin/)
src/demo/                   أدوات العرض (الإعدادات، الرحلات، السيناريوهات، الملاحظات، الترحيب)
src/ui/                     مكونات التصميم المشتركة
src/i18n/                   t('النص العربي') + en.ts (ملف الإنجليزي الوحيد) + رسايل الأخطاء
src/theme/tokens.css        ملف الثيم الوحيد
```

### اختبار سريع من غير متصفح

```bash
npx esbuild scripts/journeys-test.ts --bundle --platform=node --format=esm --outfile=/tmp/jt.mjs && node /tmp/jt.mjs
```

بيطبع `FAILURES: 0` لو كله تمام. و`node scripts/extract-i18n.mjs` بيطلع النصوص اللي لسه ملهاش إنجليزي.
